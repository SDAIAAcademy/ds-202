Every claim has a count. Rows in, rows out, rows set aside; rules run, rules failed; an estimate with its range.

Walk through each criterion with the full-marks line of the brief (labs/capstone/README.md). The repository is scored on this rubric; the live defence is scored separately on whether the rebuild runs, the corrupted input is caught by a named rule, and the participant can explain any rule pointed at.

Format

Eight minutes of defence, then four minutes of questions

1 · The question

Which question, which population, which sources. One minute, no slides needed.

2 · The rebuild

One command on the raw files. Then the assessor corrupts one input file: rebuild, and show which rule fails and why.

3 · The answer and its limits

The estimate with its range, and the one limit that matters most to the person who asked.

Peer feedback. After each defence, everyone writes one strength, one question and one suggestion.

The corruption is applied by the assessor to a raw file in the participant's working folder, by a short script, while the participant watches. A build that stops with a traceback has detected the fault and not reported it; a build that finishes with every rule green has missed it. Restore the file afterwards.
